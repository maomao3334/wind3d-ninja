# 风向坐标修正与精度校准限制

## 1.1.8 的确定性修正

输入气象风向采用来向 FROM，真北为 0 度，顺时针增加；东、北风分量分别为
`u = -speed * sin(direction)`、`v = -speed * cos(direction)`。

WindNinja 投影 ASCII 风向与原生 OpenFOAM 的水平速度使用网格 x/y 坐标。
旧版本直接将它们标成真实东/北分量，在非中央经线处引入子午线收敛角误差。
1.1.8 根据每个位置的 CRS 和坐标转换方向，不拟合任何观测偏置：

- NetCDF 的 U/V、研究验证和原生 UAV XYZ 采样输出真实东/北分量。
- 固定站 CSV 的真实东/北速度先转换到投影网格，再进入原生源项。
- KMZ 风向标签使用真北；箭头位置计算使用对应的网格速度。
- 原生同化报告保留局地收敛角、测站原始真北分量和实际网格约束分量。
- 标量 `SinsAve01min` 和矢量 `SinsVectorAve01min` 分属独立产品，不再合并。

例如 EPSG:32648、经度 102.3716、纬度 25.0256，网格北相对真北的顺时针方位
约为 -1.11253 度。纯水平坐标旋转保留风速，不能解释约 100 度的外场方向差异。
独立回归用大地线位移构造四个基本风向，并检查投影两侧位置和 KMZ 实际箭头。

## 外场精度尚未认证

### 1.1.9 最终实测复跑

2026-10-21 验收的安装版，在 UTC `2024-04-03T08:06:00Z`、50 m 高度、
200 m 分辨率下，原生基线风向圆周 MAE 为 **103.410125°**，同化后为
**103.384928°**，没有显示明显改善。风速 MAE 为 0.904539 m/s，
RMSE 为 1.066417 m/s。宿主机与全新 Windows 客机结果一致仅证明可复现，
不证明现场精度合格。

844 条验证记录中，723 条为 `time_mismatch`、91 条为 `height_mismatch`，
仅 30 条为 `ok`，覆盖 11 个不同 XYZ 位置。这些状态反映当前筛选和匹配结果，
不能据此认定原始记录错误。

独立坐标核验与 1,226 个 KMZ 箭头检查通过，降低了简单坐标转换或绘图错误的
可能性，但不能认证外部仪器数据的方向含义。当前按配置将观测解释为真北来向；
当次飞行是否满足该定义、运动补偿和时间/高度对齐仍需独立依据。现阶段不能
归咎于数据，也不能排除软件输入解释或模型误差。合成固定站只验证同化机制，
不是实测校准真值。

103° 是样本的平均绝对角误差，不是已识别的固定偏转，不能直接减去 103°
来完成校准。应先对一段实测完成方向基准、运动补偿和同时间/位置/高度核对，
再区分输入适配问题与模型误差，并使用未参与校准的数据验证。

### 历史检查点

保留的旧版原生验证中，30 条有效记录的方向平均绝对误差为 102.87114 度。
仅转换旧检查点的输出坐标后为 103.39027 度，风速误差不变。这个离线重算不代表
重新施加测站约束后的求解结果，也不证明精度提高。合成固定站用于工程回归，
不能作为真实外场湍流或风向精度的证据。

完成绝对风向校准还需要该次观测的可核验资料：

- UAV 风向是真北、磁北还是机体坐标，以及当次飞行的运动补偿定义。
- WindMaster V3.1.1 的 `in_offset=315`、`out_offset=0` 是否已经作用于导出的 Sins 产品。
- 当次飞行起飞点、海拔和高度基准。
- 设备取样时钟与雷达时钟的同步记录；PC 缓存回传时间不能替代取样时间认证。

不会自动叠加 315 度偏置，不会按验证分数切换 FROM/TO、时间字段或产品，
也不会将 UAV 验证数据用于角度拟合。应先由独立仪器或已知方位基准确定转换，
再在未参与校准的数据上报告圆周方向误差和有效样本数。

## Windows 验收范围

单元测试、现有电脑的隔离环境回归与全新 Windows 操作系统测试是三类不同证据。
本轮还复现了求解器仅靠 PATH 查找 DLL 时的启动失败；1.1.8 将两版 OpenFOAM
的 DLL 分别放到各自 EXE 旁，并在 `portable_app.json` 中记录副本哈希，
不依赖系统安装同名 DLL，也不混用两版运行库。
2026-10-21 改用可启动的全新 Windows 10 家庭中文版 19045 完成验收。先记录
无产品及无 QA Python 的基线，验证 1.1.8 后卸载，再安装最终 1.1.9；最终版本
未另行恢复空白快照。安装、诊断、常规风场、手动湍流、原生同化输出、GUI
响应及卸载保留均已检查。

原生计算超过验收脚本的 1800 秒等待上限，但产品继续运行并生成完整结果；
随后补验成功 JSON、收敛报告、六变量 NetCDF 和 KMZ。无法重新取得原始进程
退出码，记录为 null，不宣称观察到退出码 0。CLI `--json` 有一行进度前缀，
日志仍保留非致命加载及联网警告。完整范围见
[1.1.9 验证记录](../packaging/validation-v1.1.9.md)。

结论：列明场景的 Windows 工程可用性通过，现场绝对风向精度未通过验收。
